## 1. Goal

Build the front-end of the Stardust compiler: source text → tokens → lossless CST → typed AST → name-resolved, desugared HIR. Ship `sdust fmt` and `sdust check` as user-facing commands. Establish the conformance corpus (20 canonical `.sd` programs) and the test infrastructure every later slice will sit on top of.

End state for slice 1 matches spec §31.2 exit criteria:

- `sdust fmt` stable and idempotent on every example.
- AST and HIR dumps available (`sdust dump --ast|--cst|--hir`).
- Syntax error recovery with ariadne-rendered diagnostics.
- Examples parse and format idempotently in a sweep test.

## 2. Non-goals for slice 1

These belong to later slices. We parse the syntax for them and represent them in HIR, but we do not enforce their semantics.

- Type checking, inference beyond local lexical scope. (Slice 2.)
- Borrow/ownership/affine checking. (Slice 2.)
- Effect and capability checking. (Slice 2.)
- SIR lowering. (Slice 3.)
- Runtime: scheduler, agent registry, mailbox, supervisor engine. (Slice 4.)
- Native and Wasm codegen. (Slices 5–6.)
- LSP, package manager, publishing. (Slice 7.)
- Procedural macros, dependent types, distributed agents. Deferred to v0.2+ per spec §30.2.

We also do **not** parse anything outside the spec surface. If the spec doesn't define a syntax, slice 1 doesn't invent one.

## 4. Pipeline

```
source string
   ↓ logos lexer (sdust-syntax::lexer)
SyntaxKind tokens (with span + trivia)
   ↓ recursive-descent parser (sdust-syntax::parser)
rowan green tree (lossless CST)
   ↓ typed AST accessors (sdust-ast)
typed AST view
   ↓ HIR lowering (sdust-hir::lower)
name-resolved, desugared HIR (arena-allocated)
```

The CST is the source of truth for the formatter. The AST is a typed view of the CST (no separate allocation). The HIR is a separate arena with its own IDs.

## 5. Lexer

**Library:** `logos` 0.14+.

**Token kinds:** one enum `SyntaxKind` shared between lexer and rowan (rowan requires this). Generated by hand from the reserved-identifier list in spec §3.3 plus literal kinds and punctuation.

**Special-case literals** (callbacks):

- Duration literals (§3.4): `\d+(ns|us|ms|s|m|h)` → `DURATION_LITERAL`. The trailing unit is parsed at lex time; the parser later validates and converts.
- Size literals (§3.4): `\d+(B|KiB|MiB|GiB)` → `SIZE_LITERAL`. (TiB/PiB not in spec §3.4; will add when spec adds them.)
- Numeric with type suffix (§3.4): `42u32`, `3.14f64`, `0xff_u8`. Lex as one token, decompose at parse time.
- String literals: standard `"..."` with `\n`, `\t`, `\"`, `\\`, `\x..`, `\u{...}` escapes. No raw strings in slice 1 (defer to slice 2 when stdlib needs them).
- `html"..."` template literals (§4 web component example): lexed as a regular tagged-string token. The inside is **opaque** in slice 1 — we don't parse the HTML interpolation. The slice 1 HTML template is just `html"<tag>...</tag>"` with no `{expr}` interpolation. The `{n}` syntax in the spec §35 example is parsed as a separate library-level concern (deferred); for now we only lex the literal and store its inner text.

**Trivia preserved:** whitespace, line comments, block comments, doc comments. All emit tokens; the parser attaches them to nodes via rowan's standard trivia mechanism (leading + trailing trivia).

**Reserved identifiers** (spec §3.3): the lexer recognizes all 51 keywords as distinct `SyntaxKind` variants, not generic identifiers.

## 6. CST (rowan)

**Library:** `rowan` 0.15+.

Two trees: green (immutable, structural sharing) and red (cheap pointer wrapper providing parent/sibling navigation).

**Node kinds** mirror spec sections: `FILE`, `USE_DECL`, `MOD_DECL`, `FN_DECL`, `STRUCT_DECL`, `ENUM_DECL`, `TYPE_ALIAS`, `IMPL_BLOCK`, `TRAIT_DECL`, `AGENT_DECL`, `PROTOCOL_DECL`, `SUPERVISOR_DECL`, `BUDGET_BLOCK`, `SANDBOX_BLOCK`, `ARENA_BLOCK`, `TASK_SCOPE`, `EXTERN_BLOCK`, `MACRO_DECL`, `EXPR_*` for each expression form, `PAT_*` for patterns, `TYPE_*` for type expressions.

**Trivia attachment:** comments attach to the immediately following item by default (matches `rustfmt`/`prettier` behavior). Trailing same-line comments attach to the preceding item. The formatter relies on this discipline.

## 7. Parser

**Strategy:** Hand-rolled recursive descent. Expression parsing uses Pratt (precedence climbing). This matches `rustc`, `swiftc`, and `clang` because real languages need imperative control over error recovery, lookahead, and disambiguation.

**Why not combinators:** `chumsky`/`nom`/`lalrpop` make error recovery harder, not easier, on a language with `agent`/`protocol`/`on` blocks that can nest within `impl`/`mod`/expression positions. Combinators are great for grammars that fit on one page; Stardust does not.

**Error recovery:** synchronization tokens are the block delimiters and item-start keywords. On parse error inside an item, skip to the next `fn`, `agent`, `protocol`, `struct`, `enum`, `impl`, `trait`, `supervisor`, `use`, `mod`, `pub`, or matching `}`. Always emit a partial CST node containing an `ERROR` token so IDE consumers can render half-typed code.

**Operator precedence** (high → low, derived from spec usage):

1. Postfix: `.`, `()`, `[]`, `?`, `!Msg(...)`, `?Msg(...)`, `@duration`
2. Unary: `-`, `!`, `&`, `&mut`, `*`, `move`
3. `as`
4. `*`, `/`, `%`
5. `+`, `-`
6. `<<`, `>>`
7. `&` (bitwise)
8. `^`
9. `|`
10. `==`, `!=`, `<`, `<=`, `>`, `>=`
11. `&&`
12. `||`
13. `..`, `..=`
14. `=`, `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `|=`, `^=`, `<<=`, `>>=` (right-associative)
15. `return`, `break`, `continue`, `yield` (statement-level)

The spec doesn't list precedence explicitly. We adopt Rust's precedence table for the operators Rust shares; for Stardust-unique syntax (`!Msg`, `?Msg`, `@duration`), we treat them as postfix at precedence 1.

**Grammar coverage in slice 1:** the full surface of spec §3–§22, plus §26.1 extern blocks. Parse but do not semantically enforce:

- Ownership annotations (`&`, `&mut`, `move`, `mut`)
- Capability params, effect annotations (`effect net,time,alloc`)
- Public/private (`pub`)
- Generic parameters and constraints (`fn sort[T: Ord]`)
- Agent + protocol declarations with `on Msg(...)` handlers
- Send/ask: `agent!Msg(x)`, `agent?Msg(x) @2s`
- Supervisors (`supervisor`, `sup`, `child`, `on_fail`, `restart`, `backoff`, `up_to`, `in`)
- Budgets and sandboxes (`budget`, `sandbox`)
- Arenas (`arena name { ... }`, `arena name: expr`)
- Task scopes (`task scope @5s { ... }`, `task.all(...)`)
- Macros (`macro name(args) => { ... }`)
- Unsafe blocks and functions
- `extern c { ... }`, `extern js { ... }`, `export c fn`, `export component`, `export fn`
- Error sugar: `T!E`, `T!{A,B}`, `?` propagation
- Patterns: literal, identifier, wildcard, struct, enum variant, tuple, range, binding (`name @ pat`)

**Things the parser does not yet enforce, but accepts:**

- Public-API signature completeness rules (spec §6.4, §10.2).
- Unique handler names within an agent.
- Mutual exclusion of borrow forms.
- `requires` clauses on unsafe functions (§21) — we parse them as decorative metadata.

**Things explicitly out of scope for slice 1's parser:**

- `with` clauses, `where` clauses on impls — parsed as syntactic placeholders only.
- `dyn Trait` for trait objects beyond bare syntax.
- Refinement types and dependent types (spec §30.2 deferred).

## 8. AST view (`sdust-ast`)

Typed accessor structs wrap rowan `SyntaxNode` for each node kind. Pattern:

```rust
pub struct FnDecl(SyntaxNode);
impl FnDecl {
    pub fn name(&self) -> Option<Name> { ... }
    pub fn params(&self) -> impl Iterator<Item = Param> { ... }
    pub fn return_type(&self) -> Option<TypeExpr> { ... }
    pub fn effect_clause(&self) -> Option<EffectClause> { ... }
    pub fn body(&self) -> Option<Body> { ... }
}
```

Generated semi-manually from a grammar file (`crates/sdust-syntax/src/grammar.ungram`, ungrammar format). A small build script (or one-shot tool) regenerates the accessors; slice 1 may commit the generated file by hand to avoid build-script complexity until the grammar stabilizes.

## 9. HIR (`sdust-hir`)

**Allocation:** `la-arena` with indexed handles (`FnId`, `AgentId`, `ProtocolId`, `ExprId`, `PatId`, `TypeId`). Stable IDs across the lowering of one package; mapping back to CST spans via a side table.

**Lowering responsibilities:**

1. **Module collection:** walk the file/module tree, register all top-level items in a per-package symbol table.
2. **Name resolution (module-scope only):** resolve `use` paths, function calls to local module, types to local module + std imports. Cross-module resolution is correct but trait/method resolution is not. Generic constraints recorded but not solved.
3. **Desugaring:**
   - `T!E` → `Type::Result(box T, box E)`. `T!{A,B}` → `Type::Result(box T, box Type::Union([A, B]))`.
   - Expression-body fn `fn f(x) = expr` → block-body `fn f(x) { expr }`.
   - Compact agent state init `n = 0` → typed state field with inferred type slot (slot filled in slice 2).
   - Compact protocol `on Msg(args) -> body` → `on Msg(args) { body }`.
   - `arena name: expr` → `arena name { expr }`.
   - `sup Name strategy { ... }` → `supervisor Name(strategy: ...) { ... }`.
   - Sandbox/budget short form normalized to canonical layout.
4. **Effect/capability collection:** parse `effect ...` clauses into `HirEffectSet`, parse capability params into `HirCapList`. Do not check effect closure or capability narrowing yet.
5. **Span preservation:** every HIR node carries a `SourceSpan` for diagnostics.

**HIR is NOT type-checked.** Calling `hir.types()` returns syntactic type expressions, not resolved types. Slice 2 will add a `Ty` arena and a resolver.

**HIR dump format:** stable, deterministic, snapshot-friendly. S-expression-flavored, e.g.:

```
(module example
  (use std.io)
  (fn main ()
    (block
      (call log "hello, Stardust"))))
```

## 10. Diagnostics (`sdust-diagnostics`)

**Internal model:**

```rust
pub struct Diagnostic {
    pub code: DiagCode,          // e.g. DiagCode::ParseExpected
    pub severity: Severity,      // Error | Warning | Note | Help
    pub primary: Label,          // span + message
    pub secondary: Vec<Label>,
    pub notes: Vec<String>,
    pub helps: Vec<String>,
}
```

**Error codes:** `MT0001`–`MT0999` reserved for lex/parse. `MT1000`–`MT1999` for HIR. Codes are stable forever once shipped (we may rename messages, not codes).

**Render:** `ariadne` for terminal output. The `Diagnostic` type is independent of `ariadne` so we can render to JSON for LSP later without churn.

**No "did you mean" suggestions in slice 1.** Suggestions need name-resolution context and edit distance; they land in slice 2.

**Diagnostics emitted in slice 1** (illustrative, not exhaustive):

- `MT0001` unexpected token
- `MT0002` unterminated string literal
- `MT0003` invalid escape sequence
- `MT0004` unknown duration unit
- `MT0010` expected item (`fn`, `agent`, …)
- `MT0011` expected expression
- `MT0012` mismatched delimiter
- `MT0020` duplicate `on` handler in agent
- `MT0021` `pub` requires explicit return type (spec §6.4, §10.2)
- `MT1001` unresolved name
- `MT1002` use path resolves to nothing

## 11. Formatter (`sdust-fmt`)

**Algorithm:** Wadler/Lindig pretty-printer combinators. Doc grammar:

```
Doc ::= Nil
      | Text(str)
      | Line             -- forced break
      | SoftLine         -- break if group is broken
      | Nest(n, Doc)
      | Group(Doc)
      | Concat(Doc, Doc)
```

**Input:** rowan green tree (slice-1 source of truth). Operates on the CST, not the AST, so comment trivia survives.

**Style rules** (canonical short form per spec §28.1):

- `Result[T, E]` rendered as `T!E` when written that way; preserved verbatim if originally written `Result[T, E]` (round-trip identity).
- Spaces around binary operators; no space inside `[]` or `()`.
- One trailing newline at EOF, exactly.
- Empty lines: at most one blank line between items; zero blank lines at start/end of block.
- Comma trailing: yes for multi-line lists, no for single-line.
- Long lines: 100 columns default, configurable later via `star.toml`.
- Agent compact form preferred:
  ```sd
  agent Counter: Count {
    n = 0
    on Inc() -> { n += 1; n }
  }
  ```
- `arena name: expr` retained when body is a single expression; expanded to `arena name { ... }` otherwise.
- `T!E` preferred over `Result[T, E]` only when input wrote `T!E`.

**Idempotence requirement:** `fmt(fmt(src)) == fmt(src)` for every valid input. Enforced by a sweep test that runs every `.sd` in `examples/` and `tests/` through `fmt` twice.

**Round-trip requirement:** `parse(fmt(src))` produces a CST whose AST shape matches `parse(src)`'s AST shape. Comment positions need not be byte-identical but must attach to the same logical node.

## 12. CLI (`sdust-cli`, the `sdust` binary)

Slice 1 commands:

```
sdust new <name>      # scaffold star.toml + src/main.sd
sdust fmt [paths...]  # format files in place (or stdin)
sdust check [path]    # parse + HIR-lower; emit diagnostics; exit nonzero on error
sdust dump --ast      # AST dump to stdout
sdust dump --cst      # CST debug dump (rowan format)
sdust dump --hir      # HIR S-expression dump
```

Commands explicitly **not** in slice 1: `build`, `run`, `test` (we use `cargo test` for our own tests), `lint`, `doc`, `bench`, `pkg publish`, `lsp`. These come with their respective downstream slices.

`sdust new <name>` scaffolds:

```
<name>/
├── star.toml          # name, version=0.1.0, edition=2026, profile=host
└── src/main.sd        # fn main() { log("hello, Stardust") }
```

`star.toml` parsing is minimal: name, version, edition, profile, [deps] block. No `[build]` resolution yet (no targets to build for).

## 15. Test strategy

- **`insta` snapshots** for CST, AST shape (debug-printed), and HIR S-expression dump of every example.
- **`tests/fmt/idempotence.rs`** iterates `examples/*.sd` and `tests/fmt/fixtures/*.sd`, formats each twice, asserts byte-identical.
- **`tests/fmt/round_trip.rs`** asserts `parse(fmt(src))` shape matches `parse(src)` shape.
- **`tests/parser/recovery/`** holds malformed inputs with expected diagnostic codes and the partial CST shape. Snapshot tests.
- **`tests/hir/`** holds HIR dumps as snapshots. Drift triggers a snapshot review, not a silent pass.
- **`cargo test --workspace`** runs everything. CI gate: zero failures before slice closes.

## 17. Risks and mitigations

| Risk | Mitigation |
|---|---|
| `html"..."` template syntax interpolation (`{n}`) ambiguous with block syntax | Slice 1 lexes the literal as opaque; interpolation deferred to a library macro in slice 2. |
| Send/ask postfix operators (`!Msg`, `?Msg`, `@dur`) collide with logical-not and `?` propagation | Disambiguate by what follows the operator: `!`+identifier = send; `!`+expr = boolean not. `?`+identifier+`(` = ask; `?` at end of expr = propagate. Pratt parser handles this with lookahead. |
| Compact arena form `arena turn: expr` parsing | Treat `arena <name>:` as a unique two-token sequence; the parser branches on whether `:` or `{` follows the arena name. |
| Recursive descent stack overflow on deeply nested expressions | Limit nesting depth to 256 in slice 1; emit `MT0030` if exceeded. (Real fix later.) |
| Snapshot churn during early parser iteration | Use `insta review` workflow; commit snapshots once examples lock in. |

## 20. Open questions deferred to slice boundaries (not blockers for slice 1)

- Will we want a `with` clause grammar for capability narrowing (spec §8.1) in slice 1 or slice 2? Slice 1 parses `let read_only = fs.ro("/data")` as a normal method call; if the spec evolves to require a `with` block, we revisit.

- Whether HIR carries effect inference results or merely effect declarations. Slice 1 stores declarations only; slice 2 fills in inferred sets.

These do not block slice 1 because they are downstream consumers of HIR, not producers.
