# {{NAME}}

A Mighty web-game scaffold. Generated by:

```bash
mty new --template web-game {{NAME}}
```

## Run it

```bash
mty serve --watch
```

Then open <http://localhost:8000>. The `--watch` flag rebuilds on
every edit to `src/` and pushes a reload to the page over a
websocket (`/_reload`).

## Layout

```
{{NAME}}/
├── mighty.toml          # package manifest
├── src/
│   └── main.mty         # the Mighty agent (game state)
└── web/
    ├── index.html       # host page
    └── dom-shim.js      # JS host glue + canvas mirror
```

## How it works (v0.23)

- `src/main.mty` defines a `Game` agent that owns the score +
  alive flag. Each keystroke maps to a `GameInput` message and a
  matching exported entry point.
- The agent emits `log("evt:...")` lines on every state change.
- `web/dom-shim.js` loads `/main.wasm`, wires keyboard events to
  the wasm exports, and mirrors the agent's logged events onto a
  `<canvas>`.

This is the v0.22-era pattern; once the canvas WIT in
`crates/mty-codegen-wasm/wit/mty-web/canvas.wit` lands the guest
can draw to the canvas directly and the JS mirror collapses to
input plumbing.

## Build manually

```bash
# Just compile, no server:
mty build --target wasm32-web src/main.mty --out-dir web

# Or serve the built bytes one-shot:
mty serve --port 9000
```

`mty serve` reads `mighty.toml`, runs the same `wasm32-web` build,
serves `web/index.html` at `/`, `web/<asset>` for each static
asset, and the freshly built artefact at `/main.wasm`.
